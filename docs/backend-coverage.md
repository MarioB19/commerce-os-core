## Decisiones y límites explícitos

- Los registros JSONB se validan por clase pública y referencias SQL de workspace/entorno; inbox/outbox/controles/autoridades son tablas dedicadas. Las revisiones de oferta/agente/banco/política y bindings no se reescriben.
- Usuarios, tokens y comandos se crean atómicamente con Idempotency-Key. La respuesta de credencial de servicio almacenada para replay queda cifrada.
- Los endpoints devuelven 202 para comandos durables; APPLIED requiere recibo del worker. No hay endpoint vacío que simule una transición completada.
- Medios recibidos y propiedad de registros de evidencia siguen ADR-004; retención sigue ADR-005 y requiere mantenimiento separado. Las integraciones que únicamente pasaron fixtures permanecen UNVERIFIED.
- API, permisos, catálogos, import/export, conversión preparada y retención tienen implementación y pruebas locales. Despliegue real, escaneo QR, configuración bancaria/IA/proveedores y autorización de mensajes son dependencias externas concretas; no sustituyen pruebas de software.

Comandos de verificación: pnpm typecheck; pnpm lint; pnpm test:integration. Los conteos finales, E2E, carga y restore se registran en la entrega integrada, evitando sumar ejecuciones repetidas como cobertura adicional.

Índices 0010 medidos con EXPLAIN ANALYZE BUFFERS sobre la base sintética retenida de carga (5613 registros, 1840 efectos y 6296 eventos): proyección de efectos 5661.025 ms→2.865 ms; consumidor de eventos 124.016 ms→1.165 ms. Son microconsultas sobre ese conjunto, no una certificación de capacidad final. Planes completos en `docs/query-performance.json`; el coordinador ejecuta nuevamente la carga integrada.

Cierre de seguridad: esquema discriminado para comandos públicos, hash de idempotencia incluye entorno, actualización de membresías idempotente, autorizaciones validan todas las referencias de ámbito, respuesta de aprobación minimizada. Retención 0011 verifica digest/manifest dentro de PostgreSQL y restringe permisos de mantenimiento; 0012 valida jerarquía y empate temporal de bindings por prioridad. Estos controles tienen pruebas de regresión sintéticas y no aprueban operación real.

Retención 0013 serializa nuevas referencias a assets con el bloqueo del executor y rechaza referencias a objetos ya retenidos. Una evidencia financiera incorporada después del plan lo invalida al aplicar; no se borra su archivo.

La revisión final de mantenimiento valida COMOSB02 sobre todas las migraciones: dump y archivos privados, integridad de bytes, congelamiento de workspaces y ownership, SENDING→UNKNOWN y revocación de autorizaciones. Tanto la corrupción del cifrado como un archivo tar autenticado con enlaces se rechazan antes de crear la base destino. Evidencia: `docs/evidence/recovery.json`; operación y límites: `docs/backup-recovery.md`.
