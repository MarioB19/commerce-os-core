# ADR: publicación continua desde GitHub Actions

Fecha: 2026-09-07 UTC. Estado: aceptado para implementar por solicitud de Brandon.

La CI existente verifica el código, pero construir en el Mac, mover archivos por Cloud Shell e instalar manualmente domina el tiempo de entrega. GitHub Actions construirá Linux/amd64 con caché y preparará un paquete inmutable del mismo commit verificado. Los pushes de `main` podrán desplegar automáticamente; los PR sólo verifican. Un disparo manual permite repetir el pipeline de `main`.

El job de producción depende de verificación y paquete correctos. Usa el entorno GitHub `production`, concurrencia única sin cancelar un despliegue en curso y rechaza commits superados por `main` antes de instalar. Google Cloud confía sólo en los IDs de este repositorio/propietario, rama main y workflow previsto mediante OIDC/Workload Identity Federation. Una cuenta de servicio dedicada usa OS Login y túnel IAP exclusivamente sobre el VPS existente. No se exportan llaves de servicio ni credenciales de Commerce OS a GitHub.

Se reutiliza el instalador probado: backup B02 previo, migraciones, aislamiento de ownership y recreación del núcleo. Un wrapper verifica hash exterior, extracción segura, checksums internos, imágenes Linux/amd64, migraciones y salud; guarda historial y log privados. El proceso remoto vive en systemd para sobrevivir a una desconexión SSH. PostgreSQL, gateway, POC, proxy, volúmenes y perfiles de integración se preservan. No se ejecuta un runner de GitHub con acceso Docker permanente en producción.

La publicación conserva el contrato de r5: congela REAL y requiere renovar activación operativa desde la plataforma. No envía mensajes ni modifica campañas o gasto. Ante fallo conserva evidencia y el respaldo; no restaura ni revierte esquemas automáticamente. El rollback compatible continúa disponible mediante el helper existente y la configuración anterior conservada. No se afirma recuperación automática ante una migración incompatible.

Cambios de documentación no necesitan desplegar contenedores. El workflow detectará rutas de aplicación/infraestructura/scripts/dependencias; un disparo manual fuerza empaquetado y despliegue. Las pruebas, compilación y empaquetado ocurren sin credenciales productivas. Se separa creación de usuarios de CI/CD: el alta solicitada se realiza por API autenticada con auditoría existente.

Referencias: [OIDC en Google Cloud](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-google-cloud-platform), [autenticación de Google Actions](https://github.com/google-github-actions/auth), [caché BuildKit](https://docs.docker.com/build/cache/backends/gha/).
