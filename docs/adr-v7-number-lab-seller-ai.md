# RF19 — vendedor canónico con admisión de IA del perfil

Decisión previa,12-oct-2026. El vendedor del laboratorio conserva composición de
contexto, instrucciones, parser de propuesta y gates comerciales canónicos. El
adaptador de transporte usa RF14 y el puente019/021 ya revisado: ejecución
SIMULATION/TEST, credencial REAL VERIFIED y presupuesto REAL. No copia keys a la
base del motor ni reutiliza is_test de credential.verify.

El factory privado fija run/operación/variante/release/snapshot y grant nativo.
El intento corresponde al ai_run canónico. El cliente público no elige grant,
modelo, endpoint, pool ni clave. El modelo se lee del grant y catálogo nativos;
reserva e INTENT vuelven a validar su identidad y la revisión exacta de la key.
El callback comercial confirma su fase SQL antes del INTENT nativo final; ninguna
transacción permanece abierta durante el POST. Un resultado incierto no autoriza
retry/fallback ni libera reserva; los costos se conservan en microUSD con uso y
precio nativos, sin convertirlos en centavos de moneda comercial.

Primero se prepara este adaptador y se ensaya contra PostgreSQL/HTTP local
sintético. El seam processAgents y el driver se conectan en un incremento
posterior dentro de este mismo alcance; este archivo no acredita montaje ni una
llamada real a proveedor. La emisión del grant desde la autorización de iniciar
la prueba es una responsabilidad explícita del montaje API, no una autoridad
que el adaptador pueda inventar.
