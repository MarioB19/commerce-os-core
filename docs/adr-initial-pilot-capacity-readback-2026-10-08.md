# ADR — Lectura canónica de capacidad del piloto existente

Fecha: 2026-10-08. Estado: propuesta revisable; no acredita instalación ni provisión real.

`prepare-pilot.mjs` guarda `WAHA_API_KEY=sha512:<digest>` en el servidor y la clave original en `channel-pilot.env`; el webhook compartido vive en ese archivo y `ingress-pilot.env`. El administrador de capacidad anterior esperaba clave original y webhook en el archivo del servidor. Además, `compose ps -q` podía presentar un gateway detenido como ausente. Ambas diferencias impiden reconciliar legítimamente el piloto existente.

El administrador reutiliza los tres archivos privados sin rotarlos. Valida custodia mediante lstat/fstat antes y después de una lectura acotada, SHA-512 de la clave original contra el servidor, URL canónica y coincidencia de los webhooks. La compatibilidad con credenciales originales completas se conserva. La clave para el GET de sesiones viaja sólo por stdin a código Node fijo dentro del gateway; no se incluye en argv, variables Docker, salida ni excepciones. La respuesta sólo contiene conteos y los errores HTTP o de formato no se convierten en cero sesiones.

El inventario usa `compose ps --all -q` para observar también containers detenidos. Un gateway inexistente produce `GATEWAY_NOT_PROVISIONED`; un gateway existente detenido conserva su snapshot y la lectura HTTP exige `GATEWAY_STOPPED_READBACK_REQUIRED` antes de leer credenciales o ejecutar un comando remoto. `measure` omite únicamente ausencia confirmada y rechaza gateways detenidos o inválidos antes de publicar inventario o medidas. Cuando no existe overlay adicional se registra el digest real de `infra/compose/pilot.yaml`.

Este cambio no crea ni arranca el piloto inicial, no modifica perfiles, sesiones, ownership o permisos, y no convierte creación detenida en resultado canónico `VERIFIED`. El administrador conserva sus operaciones existentes. La creación técnica del primer container detenido requiere su propio plan Root aprobado; arrancar únicamente su servidor para la lectura HTTP, emitir la operación API canónica y adoptar su inventario requiere los controles vigentes y un nuevo respaldo B02 con restauración. La comprobación física y la habilitación REAL siguen pendientes.

Los 20 casos de `tests/ci/test_initial_pilot_credentials.py` entran en el discovery Python de FULL. Ejercitan archivos temporales y carreras de custodia reales, compatibilidad y errores; Docker/HTTP se sustituyen por fixtures y el JavaScript fijo corre en Node con fetch sintético. Se conservan los seis casos del administrador existente. Esto acredita la corrección local de herramientas, no la autenticación contra WAHA real. Tras revisión, se requiere una prueba Linux aislada con la imagen fijada y sin sesiones: clave correcta por stdin, clave incorrecta/ausente rechazada, conteos HTTP reales y custodia intacta; después, readback canónico del despliegue exacto bajo el actor y los controles autorizados.
