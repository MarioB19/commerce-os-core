# Inteligencia V1 · Experimental

Inteligencia persiste búsquedas versionadas BR/MX y evidencia observada. GET consulta PostgreSQL, jamás consume proveedor. El refresh explícito devuelve 202/run ID; el loop de automatización procesa texto sin equipos de render. El índice parcial por búsqueda y un lock transaccional deduplican solicitudes simultáneas de distintos usuarios. Las páginas usan operation keys durables independientes del proceso.

Búsquedas nuevas: seguimiento apagado, 2 páginas, hasta 100 anuncios. Cobertura siempre PARTIAL: una muestra de transparencia no demuestra ventas ni cobertura comercial completa. Cache TTL 24h visible; no se borra historial al caducar. Seguimiento opt-in con tope diario, máximo un pendiente y próximo intento calculado desde ahora, sin ráfagas de intervalos perdidos.

`/v1/intelligence/searches` GET/POST, `/:id` GET/PATCH, `/:id/refresh` POST; `/runs/:id` GET; `/import` POST para JSON manual con procedencia y fecha; `/offers` GET, `/:id` GET/PATCH, `/:id/analyze` POST; `/opportunities` GET/POST. Mutaciones usan Idempotency-Key, environment explícito y expected_version donde existe versión. Las oportunidades son DRAFT; Estudio crea un proyecto propio enlazado, sin copiar medios competidores ni publicar ofertas.

SearchAPI usa el engine `meta_ad_library`, filtros country BR/MX, active_status/media_type, `next_page_token`. Ads normalizados a anuncio/creativo/anunciante/landing/oferta; agrupación incluye anunciante y URL canónica completa, conservando parámetros que identifican producto (no agrupa un marketplace entero). Corregir título/etiqueta preserva historial. Ranking explica relevancia textual, fuentes, continuidad observada y variantes; no ventas/ROAS inventados. Media remota se conserva como evidencia, sin capturar ni acceder automáticamente a sus URLs.

OpenAI usa Responses, esquema JSON estricto validado de nuevo y únicamente texto efectivamente obtenido. Cache por hash de observaciones/prompt/modelo; rechazo, incompleto, IDs de fuente inventados y modalidad falsa se rechazan. El resultado es síntesis asistida, no verificación factual ni aprobación editorial. Pagos inciertos quedan UNKNOWN y no se reenvían a ciegas. Keys nunca se entregan a web/MCP/equipos.

Fuentes de contrato consultadas 2026-09-08: [SearchAPI Meta Ad Library](https://www.searchapi.io/docs/meta-ad-library-api), [países](https://www.searchapi.io/docs/parameters/meta-ad-library/country), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

Permisos: los scopes de Inteligencia se aplican a la evidencia de todo el workspace. `resource_ids` de tokens creativos limita proyectos de Estudio, no IDs de búsquedas/ofertas de investigación. La membresía activa y los scopes concedidos actualmente se verifican además de los scopes del token emitido. El idioma por defecto de BR/MX se identifica como inferido del mercado cuando la fuente no lo declara.

La migración aditiva0032 concede al rol PostgreSQL `commerce_api` SELECT/INSERT/UPDATE en las seis tablas de Inteligencia. `commerce_automation` sólo puede leer las cinco tablas del procesamiento, insertar runs/ofertas/observaciones y actualizar búsquedas/runs/ofertas/análisis; no recibe DELETE ni acceso a oportunidades, voz o identidades. Los permisos del broker siguen en0029 y los de voz API en0031. `tests/integration/creative-runtime-roles.test.ts` ejecuta las rutas reales y el loop de búsqueda, programación y análisis en una base aislada usando esos roles mediante SET ROLE. El transporte externo es una fixture identificada; no acredita consumo real.
