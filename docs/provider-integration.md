## WAHA source verification

The official [changelog](https://waha.devlike.pro/docs/overview/changelog/) lists `2026.8.2` at implementation time. [WAHA Core](https://waha.devlike.pro/docs/how-to/waha-plus/) includes former Plus features from `2026.6.1`. The [repository license](https://raw.githubusercontent.com/devlikeapro/waha/master/LICENSE) is Apache-2.0. This is a documentation/license check, not a container SBOM or remote compatibility certification. Pin the selected image digest and test before a real pilot. GOWS is first candidate; NOWEB shares the contract as comparator. Each account uses its own gateway/session volume and keys.

Implemented against [sessions](https://waha.devlike.pro/docs/how-to/sessions/), [events/HMAC](https://waha.devlike.pro/docs/how-to/events/), and [send messages](https://waha.devlike.pro/docs/how-to/send-messages/). QR uses the detailed documented `GET /api/{session}/auth/qr?format=image` contract; the overview table contains a conflicting POST label. The API limits display lifetime to 15 seconds and does not persist QR material. The adapter supports text/image/document/voice and records quality as unavailable. `WORKING` alone does not override explicit restrictions.

Configuration is server-only. Register `gateway_ref: WAHA_A` and inject `WAHA_A_URL`, `WAHA_A_API_KEY`, `WAHA_A_WEBHOOK_SECRET` into channel-worker; ingress receives only the webhook secret. Default gateway session name is `default`. Provision separate references for subsequent accounts. `INTERNAL_INGRESS_URL` supplies the private callback base. Ingress authenticates SHA512 HMAC over exact raw bytes, rejects mismatched sessions, encrypts the whole envelope, deduplicates durably, and ACKs only after commit.

## Cloud source verification

The official [Meta webhook collection](https://www.postman.com/meta/whatsapp-business-platform/folder/tduohwq/webhook-payload-reference) defines message/status envelopes. [Meta's sample repository](https://github.com/fbsamples/whatsapp-api-examples) is additional primary implementation reference. Several `developers.facebook.com` pages returned read errors in this environment; this is recorded rather than treating inaccessible documentation as verified. The adapter requires an explicit Graph version. The test value `v24.0` is a fixture parameter, not a claim that it is the latest release. Select and validate the app-supported version during authorized onboarding.

Register `gateway_ref: CLOUD_A`; inject `CLOUD_A_TOKEN`, `CLOUD_A_PHONE_NUMBER_ID`, `CLOUD_A_GRAPH_VERSION` into channel-worker and `CLOUD_A_APP_SECRET`/`CLOUD_A_VERIFY_TOKEN` into ingress. Public callback is `/webhooks/cloud/{workspace}/{account}`. HMAC SHA256 validates exact bytes. GET challenge compares the account's verify token. Normalization filters phone ID, preserves `referral`/`ctwa_clid` if actually present, retains unknown fields in the protected original, and does not merge LIDs into phones without evidence.

Cloud connection reads the configured phone's Graph resource. It does not register a WABA, pretend QR pairing is official onboarding, or change advertising linkage. Media is uploaded with multipart then referenced by ID; downloads require authenticated metadata and a whitelisted Meta media origin. Templates require an approved marker and dispatcher authorization; real template inventory/eligibility must be confirmed during integration. A remote timeout produces UNKNOWN without a second messaging HTTP request.

## AI contract and cost configuration

The OpenAI Docs skill was read. Official [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) and [file inputs](https://developers.openai.com/api/docs/guides/file-inputs) were fetched. The Responses adapter sends `store:false`, no executable tools, `text.format.type=json_schema`, `strict:true`, and a bounded `max_output_tokens`. Images use `input_image`; PDFs use `input_file` with base64 data. Local parsers still validate returned fields. No model is hardcoded; the operator chooses a model with required capabilities.

Set `OPENAI_API_KEY` only for automation-worker. Optional protected `OPENAI_BASE_URL` supports an approved endpoint. Each immutable agent configuration records `input_cost_per_million_minor`, `output_cost_per_million_minor`, `max_cost_minor`, `max_tokens`, `timeout_ms`. Environment pricing fallbacks are `AI_INPUT_COST_PER_MILLION_MINOR` and `AI_OUTPUT_COST_PER_MILLION_MINOR`. Prices are operator supplied; no guessed spend metric is reported. Conservative input reservation may reject large media before a call. Actual token usage is recorded when returned. A failed/missing price, malformed response, unsupported tool, changed conversation or takeover produces review/discard, never an external action.

The deterministic provider is a test double. It does not claim OCR. Explicit simulated receipt extractions are accepted only in SIMULATION; real receipts need configured vision or a recorded human review. RECEIPT_APPROVED is documentary approval. RECONCILED requires a separate authorized human command and protected financial evidence.
